# Output Templates

Use these templates as starting shapes. Adapt the language to the user's requested language and keep the surrounding artifact style.

These templates were distilled from real client-facing offer and vision work. They are intentionally generic so they can be reused outside any one repository.

## 1. Modular Offer Page

Use when the user needs a polished client offer page, presentation page, or long-form proposal section with several modules.

Best for:

- product expansion offers
- roadmap-based commercial proposals
- editorial or operational AI systems
- multi-block client proposals

Suggested structure:

```text
Hero
- Offer label
- Product or initiative name
- One high-level value statement

Big picture
- What the whole system becomes
- How the parts work together

Module N
- Name
- Short descriptor
- What we do
- One workflow scenario: who opens it, what they see, what they do
- Result

Next phase
- What comes after the core modules
- Why it belongs in phase 2 rather than phase 1

Summary
- What the team gets
- What distribution gets
- What management gets
- Business result
```

Good rhythm:

- `Hero` explains the commercial promise.
- `Big picture` explains the system logic.
- `Modules` explain the practical value.
- `Next phase` keeps vision from sounding vague.
- `Summary` closes the loop for decision-makers.

## 2. Product Vision Section

Use when the user needs a "vision", "next phase", "where the product is going", or roadmap-opening section.

Best for:

- roadmap decks
- proposal intros
- product strategy pages
- "what v2 becomes" sections

Suggested structure:

```text
Eyebrow
Headline
2-3 sentence vision statement

Flow or contours
- Signal / input layer
- Recommendation / structuring layer
- Preparation / execution layer
- Handoff / publishing / decision layer
```

What this section should do:

- move from tool to system
- explain how the product changes the workflow
- avoid sounding like generic AI future-talk

Good pattern:

```text
The next phase moves the product from a writing tool to a working environment for the team: it helps find topics, shapes material faster, and shortens the path to publication.
```

## 3. Package / Priced Proposal

Use when the user needs a phased commercial proposal with packages, blocks, or implementation stages.

Best for:

- implementation proposals
- migration + feature rollout offers
- fixed-scope package descriptions

Suggested structure per package:

```text
Block / Package number
Name
Price or commercial marker

What it is
What is included
What the client gets
Result
```

This structure works especially well when the user wants:

- budget control
- phased delivery
- business clarity per investment block

## 4. Technical Wishlist -> Commercial Module

Use when the source material is a raw feature list, API wishlist, discovery notes, or a product brainstorm.

Suggested transformation:

```text
Raw input
- endpoints
- metrics
- integrations
- internal labels

Commercial output
- module name
- who uses it
- what they see
- what decision it enables
- what business result it drives
```

Example transformation:

```text
Raw:
- Content API
- Article Analytics API
- Traffic Sources API
- Time Series API

Commercial:
Контент-аналітика
Випусковий відкриває екран аналітики, бачить, які матеріали ростуть, які просідають і які варто допрацювати замість списувати.
Результат: редакція швидше знаходить точки росту і краще розподіляє увагу між темами, форматами та авторами.
```

## Choosing Between Templates

- Use `Modular Offer Page` when the user is selling a multi-part initiative.
- Use `Product Vision Section` when the user needs positioning before the modules.
- Use `Package / Priced Proposal` when scope and budget blocks matter.
- Use `Technical Wishlist -> Commercial Module` when the input is still too raw to show to a client.
