# Rewrite Patterns

Use these patterns when the text already exists but reads too internal, too abstract, or too technical.

## 1. Replace Internal Product Terms

Prefer plain client-facing wording.

Examples:

- `analytics layer` -> `analytics screen`, `analytics tool`, `management view`
- `platform content` -> `content for different platforms`
- `signal collection layer` -> `topic monitoring`, `trend tracking`, `competitor monitoring`
- `follow-up ideas` -> `ideas for continuing the topic`
- `behavior factor` -> `reader engagement`, `where readers drop off`, `how far people read`

## 2. Add Workflow Clarity

If a section only says what the feature does, add who uses it and what happens next.

Pattern:

```text
Role opens X, sees Y, and does Z.
```

Examples:

```text
The editor opens the enhancement step, sees which parts of the topic are still underdeveloped, and strengthens the material before publication.
```

```text
Редактор відкриває окремий крок, отримує готові підказки по тексту і відразу бачить, як зробити матеріал глибшим, цікавішим і краще структурованим.
```

## 3. Keep Strong Results, Add Mechanism

Do not weaken strong result language by default. Instead, show why the result follows.

Weak:

```text
Improves distribution.
```

Better:

```text
Improves distribution by preparing ready-to-publish Telegram, Instagram, and Threads versions from one source article.
```

## 4. Turn Vision Into Sequence

If the copy sounds like future AI fog, convert it into phases or flow.

Pattern:

```text
First the system finds the topic.
Then it helps shape the material.
Then it prepares the output for publication or distribution.
Then it shows what worked.
```

## 5. Separate Present Value From Next Phase

When the offer contains both current modules and future ideas, make the distinction explicit.

Good labels:

- `What we launch now`
- `Core modules`
- `Next phase`
- `After the base system is in place`

This prevents the offer from sounding like one undifferentiated pile of promises.

## 6. Preserve Density When the Artifact Needs It

Not every offer should be shortened aggressively.

Keep density when:

- the artifact is a deck or strategy page, not a landing page
- the buyer expects substance
- the modules need comparison
- the offer is evaluated by managers, not casual readers

Shorten only when the density blocks comprehension.
